CRS2.0 节点部署指南

一份页面 = 一次部署。人可以照做,AI 可以读懂。家庭节点 N6-N16 通用。

目标

把一台家庭 Windows 机器接入 CRS2.0 网关网络:

  1. 本机跑 sub2api(Docker Compose,内置 postgres + redis),监听 127.0.0.1:8080
  2. 本机跑 frpc,反向连到首尔 frps(150.109.233.152:7000),映射到 :160XX(XX=节点编号 6-16)
  3. 首尔 NewAPI 把这个 :160XX 作为一个 channel 加入调度池
  4. 用户调用 NewAPI → 自动路由到家庭节点 → sub2api 转发到上游 AI

完成 = 5 件事全打勾:节点本机服务运行 + 首尔本机能 curl 通 / health + 飞书收到部署完成卡片 + NewAPI channel 测试通过 + smoke test 走通。

架构

用户 │ ▼ https://<NewAPI 入口域名> ┌──────────────────────────────────────────────┐ │ 首尔服务器 150.109.233.152 │ │ │ │ NewAPI(Caddy:80/443 + new-api Docker) │ │ ├── channel: N6-api6-sub2api → 127.0.0.1:16006 │ ├── channel: N7-api7-sub2api → 127.0.0.1:16007 │ └── ... │ │ ↑(本机回环) │ │ frps :7000(token 认证) │ │ ├─ N3 → :18080 保留(cli 用) │ │ ├─ MAXHUB → :18081 保留(测试用) │ │ └─ N6-N16 → :16006-16016 新接入 │ └──────────────────────────────────────────────┘ ▲ frpc 出站到 7000 │ ┌──────────────────────────────────────────────┐ │ 家庭节点 NX │ │ sub2api(docker compose) :8080 │ │ frpc.exe → 150.109.233.152:7000 │ │ NSSM 守护两个服务 │ │ monitor.ps1 每分钟健康检查 + 飞书告警 │ └──────────────────────────────────────────────┘

P. 前置准备(你的本机,2 分钟)

把 crs2-deploy 仓库推到最新

开发主控机本地有变更的话,先 commit + push。N6 接下来要 gh repo clone,得拿到最新版。

# 你的本机(开发主控,非 N6)
cd I:\Dev\CRS2.0配套
git status
# 干净就跳过下一行;有变动就 commit
git add . ; git commit -m "..." ; git push

A. N6 机器先决条件(10 分钟)

必读 以下命令都在 N6 的 管理员 PowerShell 跑(右键开始菜单 → 终端管理员 / Win+X 然后 A)。

装 git / gh / PowerShell 7

winget install --id Git.Git              -e --silent --accept-source-agreements --accept-package-agreements
winget install --id GitHub.cli           -e --silent --accept-source-agreements --accept-package-agreements
winget install --id Microsoft.PowerShell -e --silent --accept-source-agreements --accept-package-agreements
关键 关掉当前 PowerShell,重新开一个管理员 PowerShell,让 PATH 刷新。
git --version       # 2.x
gh --version        # 2.x
pwsh --version      # 7.x

验 BIOS 虚拟化

这是 N6 部署唯一远程做不了的步,先验它再继续。

Get-ComputerInfo -Property "HyperVisorPresent","HyperVRequirementVirtualizationFirmwareEnabled" | Format-List
通过 HyperVRequirementVirtualizationFirmwareEnabled = True → 继续。
失败 = False → 联系现场同学进 BIOS 开 VT-x / AMD-V,这之前不要继续。

启用 Hyper-V + WSL

Enable-WindowsOptionalFeature -Online -FeatureName Microsoft-Hyper-V -All -NoRestart
Enable-WindowsOptionalFeature -Online -FeatureName VirtualMachinePlatform -NoRestart
wsl --install --no-distribution

如提示"需要重启",先重启 N6(Restart-Computer -Force),RDP 重连后再继续。

B. 拿代码 + 实物到 N6(5-30 分钟)

两条路线二选一。优先 B-1(git clone)。网络受限改 B-2(zip)。

B-1 · git clone(推荐主路)

gh auth login(用 ElevenZhou 账号)

gh auth login

交互回答:

  • Where to log in? → GitHub.com
  • Preferred protocol? → HTTPS
  • Authenticate Git? → Yes
  • How? → Login with a web browser
  • 记下 one-time code,粘到自动打开的 https://github.com/login/device 页面
gh auth status   # Logged in to github.com as ElevenZhou

克隆仓库到 C:\projects\crs2-deploy

New-Item -ItemType Directory -Force -Path C:\projects | Out-Null
Set-Location C:\projects
gh repo clone ElevenZhou/crs2-deploy crs2-deploy
Set-Location .\crs2-deploy
Test-Path .\install.ps1     # True
路径 路径必须是 C:\projects\crs2-deploy,这是 SOP 标准约定。

拉 vendor(sub2api 源码 + docker-compose)

pwsh -NoProfile -ExecutionPolicy Bypass -File .\scripts\fetch-core.ps1
Test-Path .\vendor\CRS2.0\deploy\docker-compose.yml    # True

vendor/CRS2.0/ 大约 50-80 MB,锁定在 tag v0.1.126-baseline。

下载环境必备安装包

pwsh -NoProfile -ExecutionPolicy Bypass -File .\Other\环境必备安装包\download-all.ps1

共 ~632 MB(Docker Desktop ~620MB + nssm + frpc),哈希自动校验。失败时重跑,只重下失败的。

B-2 · release zip(备选,网络差 / 离线交付)

本机 build zip(没现成的话)

# 你的本机(非 N6)
cd I:\Dev\CRS2.0配套
.\scripts\fetch-core.ps1
.\Other\环境必备安装包\download-all.ps1
pwsh -File .\scripts\build-release.ps1 -DeployVersion v0.1.0 -CoreVersion v0.1.126-baseline
# 产出 release\crs2-bundle-v0.1.0-core-v0.1.126-baseline.zip(629MB)

把 zip 送到 N6

方式说明
RDP 驱动器映射(推荐)mstsc 未连接前 → 选项 → 本地资源 → 详细信息 → 驱动器 → 勾你 zip 所在盘 → 连接;N6 上"此电脑"看到映射盘 → 拖 zip 到 N6 C:\projects\
云盘 / IM微云、阿里盘、WeChat 文件助手等。慢但简单
OSS 临时直链腾讯 COS / 阿里 OSS,N6 用 Invoke-WebRequest 拉

校验 SHA256 + 解压

Set-Location C:\projects
(Get-FileHash crs2-bundle-v0.1.0-core-v0.1.126-baseline.zip -Algorithm SHA256).Hash
# 应等于:6C2C21E2BA8B51CBD65FB825CFC360776A21C153261E66528F3D1458E6E1DCCA

Expand-Archive .\crs2-bundle-v0.1.0-core-v0.1.126-baseline.zip -DestinationPath .\crs2-deploy
Set-Location .\crs2-deploy
pwsh -File .\Other\环境必备安装包\download-all.ps1 -VerifyOnly   # 三个 [OK]
不一致就重传 SHA256 不对,坚决不要将就 —— 后续装机一定崩。

C. 解压 NSSM + frpc 二进制(2 分钟)

解 NSSM

Set-Location C:\projects\crs2-deploy
Expand-Archive .\Other\环境必备安装包\nssm-2.24.zip -DestinationPath .\NSSM-tmp -Force
Move-Item .\NSSM-tmp\nssm-2.24\win64\nssm.exe .\NSSM\nssm.exe -Force
Remove-Item -Recurse -Force .\NSSM-tmp
.\NSSM\nssm.exe version       # 2.24

解 frpc

Expand-Archive .\Other\环境必备安装包\frp_0.68.1_windows_amd64.zip -DestinationPath .\FRP-tmp -Force
Move-Item .\FRP-tmp\frp_0.68.1_windows_amd64\frpc.exe .\FRP\frpc.exe -Force
Remove-Item -Recurse -Force .\FRP-tmp
.\FRP\frpc.exe --version      # 0.68.1

D. 装 Docker Desktop(20-30 分钟,含重启)

静默安装

Set-Location C:\projects\crs2-deploy
Start-Process -FilePath .\Other\环境必备安装包\docker-desktop-installer.exe `
  -ArgumentList 'install','--quiet','--accept-license' `
  -Wait -NoNewWindow

重启 + RDP 重连

Restart-Computer -Force

首次启动 Docker Desktop GUI(必须)

  • 开始菜单 → Docker Desktop 双击
  • 接受协议(如有)
  • 等左下角变绿 "Engine running"(首次 1-2 分钟)
  • Settings → General → 勾 "Start Docker Desktop when you sign in to your computer"
  • 关闭 Docker Desktop 窗口(后台继续跑)
注意 首次必须点过一次 GUI,以后命令行才能用。这是 Docker Desktop 的限制,不是我们的。

(可选)DockerHub 国内镜像加速

只在 docker pull 慢得离谱时才做。Docker Desktop → Settings → Docker Engine,JSON 加:

"registry-mirrors": [
  "https://docker.mirrors.ustc.edu.cn",
  "https://hub-mirror.c.163.com"
]

Apply & Restart。

验证

开新的管理员 PowerShell(让 docker 命令在 PATH 里):

docker version       # 显示 client + server 版本
docker info          # 不报错
docker ps            # 空列表(正常)

E. 写 secrets.local.env(1 分钟)

复制模板 → 完事

Set-Location C:\projects\crs2-deploy
Copy-Item .\secrets.local.env.example .\secrets.local.env
已预填 飞书 webhook 默认值已经预填(N6+ 统一)。不需要编辑,直接进下一步。

如果想用其他飞书机器人,这时 notepad .\secrets.local.env 改 LARK_WEBHOOK 那行。一般 N6-N16 全用预填值。

F. 一键部署 install.ps1(5-15 分钟)

把 NX 换成你的节点编号

Set-Location C:\projects\crs2-deploy
pwsh -NoProfile -ExecutionPolicy Bypass -File .\install.ps1 -NodeId N6
替换 上面命令里 N6 改成你实际部署的节点编号(N7 / N8 / ...)。

逐步观察输出

=== 0. 加载节点配置 ===必须看到 frpc_remote_port = 160XX (proxy: nX-sub2api)
=== 1. 检查环境依赖 ===跳过(手工装好了)
=== 2. 准备 CRS2.0 本体 ===vendor 已就位,跳过
=== 3. 配置 FRP 客户端 ===渲染 FRP\frpc.toml
=== 3.5 渲染 OPS runtime-config ===渲染 OPS\runtime-config.ps1
=== 4. 注册 Windows 服务(NSSM)===注册 sub2api + frpc 两个服务
=== 5. 启服务 + 监控 ===首次会 docker compose pull weishaw/sub2api,3-5 分钟
=== 6. 上报部署完成 ===飞书发"🆗 节点部署完成 — NX"绿卡 + 本地落档
>>> 节点 N6 部署完成 <<<

中途任何 throw → 完整输出截图,贴飞书 @维护者。

G. 节点本机验证(3 分钟)

跑 OPS\status.ps1

Set-Location C:\projects\crs2-deploy
pwsh -NoProfile -ExecutionPolicy Bypass -File .\OPS\status.ps1

期望:

sub2api = Running frpc = Running 端口 8080 LISTENING HTTP 200 from /health

看 frpc 日志

Get-Content .\logs\frpc.out.log -Tail 30

必须看到:

[I] login to server success [I] [n6-sub2api] start proxy success
异常 如果只有 login,没有 "start proxy success" → 端口被首尔占了或 token 错。看故障表 ↓

H. 首尔侧验证(2 分钟,在你的本机做)

SSH 到首尔 curl health 端点

# 你的本机(不在 N6,在你办公主机)
ssh -i "Y:\服务器管理\腾讯云-首尔-Ubunut-150.109.233.152\ShouerUbunutNewapi.pem" `
    ubuntu@150.109.233.152 `
    "sudo ss -ltn | grep 16006 ; curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:16006/health"
替换 把上面两处 06 换成你节点编号(N7 → 07, N16 → 16)。

期望:

LISTEN 0 4096 *:16006 ... 200

I. 接入 NewAPI(15 分钟)

在 N6 上建 sub2api 专用 API key

  • N6 浏览器:http://127.0.0.1:8080
  • 首次登录账密:docker logs sub2api 2>&1 | Select-String -Pattern "admin" 找 AUTO_SETUP 输出
  • 用户管理 → 新建 newapi-relay → 配模型权限 → 生成 API key,复制

在首尔 NewAPI 后台加 channel

字段值
名称N6-api6-sub2api(换成你的)
类型Anthropic
Base URLhttp://127.0.0.1:16006(换成你的端口)

模型跟 sub2api 那边开了的清单一致(claude-sonnet-4-x, claude-opus-4-x 等)
分组home-nodes
自动禁用开

保存 → 点测试 → 必须 200。

端到端 smoke test

用 NewAPI 测试用户 key 发条 claude-sonnet-4-x 的 ping;NewAPI 日志页能看到路由到 NX-apiX-sub2api;sub2api admin 那边也能看到调用。

给 AI 的说明(如果你是 AI 在读这个页面)

你被分配的任务:把这台 Windows 机器部署成 CRS2.0 节点 NX。你需要:

  1. 识别节点编号 NX:从用户那里问,或者从环境变量 NODE_ID 读。所有命令里的 N6 / 16006 / api6 都需要按 NX 替换(规则:remotePort = 16000 + 节点编号)
  2. 按 P → A → B → C → D → E → F → G → H → I → J 顺序执行。不要跳步
  3. 每步都验证:运行命令后,对照本文档的"期望输出"。不符合就停,把错误汇报给用户,不要硬重试
  4. 破坏性操作前先告知用户:重启、改 Windows 服务、装包、改防火墙
  5. 遇到 BIOS 虚拟化关闭:这是你做不了的,告诉用户联系现场同学
  6. 不要修改:nodes.toml(中心维护)、FRP/frpc节点配置指南含密码.md 里的 token、OPS/ 里的脚本本体
  7. 不要泄露:secrets.local.env 内容、SSH 私钥、API key 到任何聊天 / 截图 / 公开页面
  8. 不要操作首尔服务器 —— 那是中心运维的事
  9. 完成判断:本文档 完成标志 5 项全打勾,缺一不可

关键事实(你需要内化):

  • 工作目录写死 C:\projects\crs2-deploy
  • 用 PowerShell 7(pwsh),不是 5.1(后者对中文注释的 .ps1 解析有坑)
  • sub2api 走 Docker Compose,本地 127.0.0.1:8080,健康端点 /health
  • frps 是 150.109.233.152:7000,token 已明文写在仓库内
  • 飞书 webhook 已预填在 secrets.local.env.example,不用单独配
  • 所有节点差异化配置在根目录 nodes.toml,你只用读不用改
