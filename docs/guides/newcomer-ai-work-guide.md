# 新人开始用 AI 工作指南

Updated: 2026-05-15

## 核心判断

新人不要只把 AI 当聊天工具。真正能提升效率的方式，是让 AI 进入真实工作环境，看到项目、文件、目录和运行结果，参与分析、修改、验证和沉淀。

## 常见误区

很多新人一开始会使用云端机器人、飞书对话框、网页 AI 工具或 OpenClaw 之类入口。它们适合轻量问答，但不适合处理本地复杂任务，因为通常无法直接读取本地文件、本机服务、局域网资源或完整项目目录。

一句话边界：云端机器人不能凭空读取你的本地文件和局域网环境。

## 推荐工具顺序

1. Codex：首选，适合本地项目分析、代码修改、命令执行、文件整理和任务闭环。
2. Trae / Trae Solo：适合 IDE 内开发，适合喜欢图形化编辑环境的新人。
3. WorkBuddy：适合本地文件整理、资料分析和日常工作辅助。
4. 豆包 / 通用聊天 AI：适合概念解释、小问题、简单报错和快速问答。
5. 飞书机器人 / 云端机器人：适合群内轻量问答、通知和协作，不适合依赖它处理本地项目。

## 使用前检查

- 算力、积分、额度或 token 是否用光。
- 当前工具是否能访问你的本地工作目录。
- Codex、Trae 或 WorkBuddy 是否打开了正确项目路径。
- 任务描述是否包含目标、报错、文件路径、已尝试方案和期望输出。
- 是否有不能做的事，例如不要删除文件、不要提交代码、先只分析。

## 推荐工作流程

1. 判断任务类型：知识问答、小报错、本地项目、本地文件、文档整理、自动化或复杂排查。
2. 选择工具：简单问题问豆包或通用 AI；涉及本地上下文时优先用 Codex / Trae / WorkBuddy。
3. 给清楚任务：说明目标、材料位置、当前现象、已尝试方案和输出要求。
4. 先分析再执行：先让 AI 看结构、判断原因、列方案，再允许修改或批处理。
5. 执行后验证：让 AI 说明改了哪些文件、为什么改、怎么验证、还有什么风险。
6. 沉淀结果：把有效提示词、流程、踩坑和产出提交到工作台或飞流AI枢纽。

## 升级求助规则

如果工具选对了、本地 Agent 能访问项目、额度正常、问题描述清楚，且 AI 已经尝试分析和修复，但仍然解决不了，就找蔡或老周。

求助时要带上：使用的工具、问过 AI 的内容、AI 的结论、已经尝试的方案、当前卡点、相关路径、报错或日志。

## 一句话版本

简单问题可以问豆包、飞书机器人或 Codex；只要涉及本地项目、本地文件、局域网环境、代码修改、文档整理，就不要指望云端机器人直接搞定。尽早使用本地 Agent，优先 Codex，其次 Trae / Trae Solo，再到 WorkBuddy。先检查积分和算力，再让 AI 分析问题。Codex 解决不了的，再找蔡或老周。
