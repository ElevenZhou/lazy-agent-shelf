  1. 安装 Docker Desktop，并确保 Docker Engine 正常运行。
  2. 安装 Node.js LTS，确保 node 和 npm 可用；后续安装 Codex CLI、OpenCode CLI 或其他前端工具都会用到。

4. CLIProxyAPI 安装与启动

4.1 拉取或确认项目

如果是新机器，先从 GitHub 拉取 CLIProxyAPI 主项目：

cd /d C:\Projects
mkdir CLIProxyAPI
git clone https://github.com/router-for-me/CLIProxyAPI.git CLIProxyAPI\CLIProxyAPI

如果同事还需要管理中心源码，也可以单独拉取第二个仓库：

cd /d C:\Projects\CLIProxyAPI
git clone https://github.com/router-for-me/Cli-Proxy-API-Management-Center.git Cli-Proxy-API-Management-Center

如果目录已经存在，进入项目目录并确认关键文件：

cd /d C:\Projects\CLIProxyAPI\CLIProxyAPI
dir README_CN.md docker-compose.yml config.example.yaml

后续更新主程序源码时使用：

cd /d C:\Projects\CLIProxyAPI\CLIProxyAPI
git pull
Cli-Proxy-API-Management-Center 是管理面板源码仓库，普通部署不需要单独拉取。CLIProxyAPI 服务启动后会直接通过 /management.html 提供管理页；只有需要改 UI、重新构建管理页或查看前端源码时才需要拉取它。

4.2 创建配置文件

如果还没有 config.yaml，先从模板复制：

cd /d C:\Projects\CLIProxyAPI\CLIProxyAPI
copy config.example.yaml config.yaml

编辑 config.yaml，最少确认以下字段：

host: "127.0.0.1"
port: 8317

remote-management:
  allow-remote: true
  secret-key: "<填写强管理密钥，首次启动后可能会被程序哈希化>"

auth-dir: "~/.cli-proxy-api"

api-keys:
  - "<给 NewAPI 或客户端使用的代理 API Key>"

logging-to-file: true

说明：

  • host: "127.0.0.1" 表示 CLIProxyAPI 只允许本机访问，适合配合本机 frpc 转发。
  • remote-management.allow-remote: true 允许通过转发或非 localhost 访问管理 API，但仍需要管理密钥。
  • remote-management.secret-key 是管理面板密钥，不是客户端调用 API 的 key。
  • api-keys 是客户端、NewAPI、OpenAI SDK 调用 /v1/chat/completions 等接口时用的 key。

4.3 使用 Docker Compose 启动

在主项目目录执行：

cd /d C:\Projects\CLIProxyAPI\CLIProxyAPI
docker compose up -d

当前 docker-compose.yml 会使用镜像 eceasy/cli-proxy-api:latest，并挂载：

./config.yaml  -> /CLIProxyAPI/config.yaml
./auths        -> /root/.cli-proxy-api
./logs         -> /CLIProxyAPI/logs

常用维护命令：

docker ps
docker logs --tail 100 cli-proxy-api
docker compose restart
docker compose pull
docker compose up -d

4.4 验证本机服务

curl http://127.0.0.1:8317/
curl -I http://127.0.0.1:8317/management.html

正常返回示例：

{"endpoints":["POST /v1/chat/completions","POST /v1/completions","GET /v1/models"],"message":"CLI Proxy API Server"}

5. 管理面板使用

CLIProxyAPI 从 6.0.19 起自带管理面板。服务启动后，打开：

http://127.0.0.1:8317/management.html

连接时填写：

API 地址 http://127.0.0.1:8317 或 127.0.0.1:8317
管理密钥 填写 config.yaml 中 remote-management.secret-key 对应的明文管理密钥。

管理面板可做的事：

  • 基础设置：调试、重试、日志、代理 URL、WebSocket 鉴权等。
  • API Keys：维护给 NewAPI 或客户端使用的代理 API Key。
  • AI Providers：配置 Gemini、Codex、Claude、Vertex、OpenAI 兼容供应商、Ampcode。
  • 认证文件：上传、下载、删除 OAuth JSON 凭据。
  • OAuth：发起 Gemini、Codex、Claude、Antigravity、Kimi 等登录流程。
  • 配置文件：直接在浏览器里编辑 config.yaml 并保存。
  • 日志：查看、搜索、下载错误日志。
管理密钥保存在浏览器 localStorage 中，虽然有轻量混淆，但仍按敏感信息处理。建议用专门浏览器配置文件管理。

6. frp 首尔转发链路

6.1 下载 frp 客户端

frp 需要单独下载。当前本机脚本引用的程序路径是：

C:\Projects\claude-workspace\frp_0.68.1_windows_amd64\frpc.exe

新机器建议使用同版本，避免客户端和服务器版本差异带来兼容问题。PowerShell 下载和解压示例：

mkdir C:\Projects\claude-workspace
cd C:\Projects\claude-workspace
Invoke-WebRequest `
  -Uri "https://github.com/fatedier/frp/releases/download/v0.68.1/frp_0.68.1_windows_amd64.zip" `
  -OutFile ".\frp_0.68.1_windows_amd64.zip"
Expand-Archive ".\frp_0.68.1_windows_amd64.zip" -DestinationPath "." -Force
dir .\frp_0.68.1_windows_amd64\frpc.exe

如果服务器端 frps 后续升级，客户端也应下载相同或兼容版本，并同步修改 run-frpc-seoul.ps1 里的 $frpc 路径。

Windows 安全中心 / Microsoft Defender 可能会把 frpc.exe、frp 压缩包或启动脚本误判为风险文件并隔离。下载和解压后，应在确认来源为 frp 官方 GitHub release 的前提下，把 frp 客户端目录加入“排除项/允许列表”，避免后续被误删导致转发中断。

6.1.1 将 frp 加入 Windows 安全中心排除项

推荐只把 frp 客户端目录加入排除项，不要把整个 C:\Projects 或系统盘加入排除项。

  1. 打开 Windows 安全中心。
  2. 进入 病毒和威胁防护。
  3. 进入 病毒和威胁防护设置，点击 管理设置。
  4. 找到 排除项，点击 添加或删除排除项。
  5. 选择 添加排除项 → 文件夹。
  6. 添加目录：C:\Projects\claude-workspace\frp_0.68.1_windows_amd64。

如果 frpc.exe 已经被隔离，先到 Windows 安全中心的“保护历史记录”中恢复文件，再加入排除项。恢复后重新执行：

dir C:\Projects\claude-workspace\frp_0.68.1_windows_amd64\frpc.exe
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "C:\Projects\CLIProxyAPI\frp-seoul-cliproxyapi\run-frpc-seoul.ps1"

6.3 创建 frpc 启动脚本

新机器如果没有这些文件，可以按下面创建。先建立目录：

mkdir C:\Projects\CLIProxyAPI\frp-seoul-cliproxyapi

run-frpc-seoul.ps1 内容：

$ErrorActionPreference = 'Continue'
$frpc = 'C:\Projects\claude-workspace\frp_0.68.1_windows_amd64\frpc.exe'
$cfg = 'C:\Projects\CLIProxyAPI\frp-seoul-cliproxyapi\frpc.toml'

$err = Join-Path $wd 'frpc.err.log'
& $frpc -c $cfg >> $log 2>> $err

start-frpc-seoul-hidden.vbs 内容：

Set shell = CreateObject("WScript.Shell")
shell.Run "powershell.exe -NoProfile -ExecutionPolicy Bypass -WindowStyle Hidden -File ""C:\Projects\CLIProxyAPI\frp-seoul-cliproxyapi\run-frpc-seoul.ps1""", 0, False

7. NewAPI 对接地址

如果 NewAPI 运行在首尔服务器 Docker 容器里，渠道 Base URL 填：

http://172.17.0.1:18080

如果 NewAPI 直接运行在首尔服务器宿主机上，渠道 Base URL 填：

http://127.0.0.1:18080

原因：Docker 容器里的 127.0.0.1 是容器自身，不是宿主机；172.17.0.1 是默认 Docker bridge 下宿主机网关地址。

NewAPI 渠道里使用的鉴权 key，应填写 CLIProxyAPI config.yaml 里的 api-keys，不是管理密钥。

Docker 容器启动后配置没生效 确认挂载的是 C:\Projects\CLIProxyAPI\CLIProxyAPI\config.yaml，修改后执行 docker compose restart。

9. 安全注意事项

  • 不要把真实 frp token、SSH 私钥、服务器密码、API Key、管理密钥写进可转发文档。
  • 不要把 Fuwuqi 目录整体发给无关人员，里面可能包含私有凭据。
  • frp 客户端只从官方 GitHub release 下载；加入 Defender 排除项前先确认文件来源，不要给未知程序放行。
  • Windows 安全中心排除项只添加 frp 客户端目录，不要排除整个 C:\Projects、用户目录或系统盘。
  • CLIProxyAPI 建议保持 host: "127.0.0.1"，通过 frp 或反向代理暴露必要入口。
  • 服务器 18080 跑通后建议关闭公网访问或加来源白名单。
  • 定期轮换 frp token、管理密钥和客户端 API Key。
  • 如果怀疑泄露，立即更换 token/key，并重启 Docker 容器和 frp 服务。
部署前必须确认管理员已提供必要凭证。缺少凭证时，不要临时绕过鉴权或把服务暴露到公网；应在交付报告的“残留问题”里明确写出缺少哪一项。
